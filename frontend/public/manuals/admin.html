คู่มือนี้สำหรับบัญชี ผู้ดูแลระบบ (admin) เมนูทั้งหมดอยู่ที่ ☰ เพิ่มเติม → หัวข้อ "ผู้ดูแลระบบ" admin ทำงานของงานกิจกรรมได้ทั้งหมด (ดู คู่มือเจ้าหน้าที่งานกิจกรรม) และงานของเจ้าหน้าที่บุคลากรได้ทั้งหมด (ดูคู่มือเจ้าหน้าที่บุคลากร) รวมถึงสร้างรายงานสรุปการปฏิบัติงานประจำวันแทนเมื่อเจ้าหน้าที่บุคลากรไม่อยู่

1. ก่อนเปิดใช้จริง

  • ☐ เปลี่ยนรหัสผ่านบัญชี admin เป็นรหัสที่คาดเดายาก (โปรไฟล์ → เปลี่ยนรหัสผ่าน)
  • ☐ ตั้งเวลาเช็กชื่อกลับเป็น 07:30–08:30 น. และวันเข้าแถวปกติ จ–ศ (ถ้าเคยตั้งเพื่อทดสอบ)
  • ☐ ตั้งพื้นที่เข้าแถวบนแผนที่ และเลือกวิธีเช็กชื่อ GPS หรือ QR
  • ☐ กำหนดบทบาท: หัวหน้าแผนก ผู้บริหาร งานกิจกรรม เจ้าหน้าที่บุคลากร ตัวแทนแผนก และผู้ไม่ต้องเข้าแถว · กำหนดประเภทบุคลากรให้ครบทุกคน (ส่งออก Excel → เติมคอลัมน์ “ประเภทบุคลากร” → นำเข้า) และเพิ่มบัญชีคนที่ยังไม่มี เช่น นักศึกษาฝึกสอน
  • ☐ ตรวจผู้ลงนาม 3 ลำดับและหน่วยงานในแบบรายงาน แจ้งผู้ลงนามทุกท่านให้เข้าระบบครั้งแรก
  • ☐ ตั้งปฏิทินวันหยุดนักขัตฤกษ์และภาคเรียน
  • ☐ ตั้งค่าอีเมล SMTP บนเซิร์ฟเวอร์ (หัวข้อ 9 — เปิดการรีเซ็ตรหัสผ่านทางอีเมลและแจ้งเตือนการลงนาม) และกรอกอีเมลบุคลากรให้ครบ และ LINE Login (ถ้าต้องการ)
  • ☐ ลบข้อมูลจำลองและข้อมูลทดสอบ แล้วสำรองฐานข้อมูล 1 ครั้ง และดาวน์โหลดไฟล์กู้คืนทั้งระบบเก็บไว้นอกเซิร์ฟเวอร์ (หัวข้อ 6)
  • ☐ แจ้งครูทุกคนให้เข้าระบบด้วยรหัสพนักงาน + รหัสเริ่มต้น และตั้งรหัสใหม่ภายใน 1–2 วัน

กล่อง "วันนี้"

บอกสถานะจริงของวันนี้ (เปิดเช็กชื่ออยู่ / ยังไม่ถึงเวลาเปิด / ปิดแล้ว / ไม่มีการเข้าแถว) ถ้าปฏิทินตั้งทับวันเข้าแถวปกติจะขึ้น ⚠ พร้อมรายการ 30 วันข้างหน้า แตะ ยกเลิกการตั้งนี้ ได้ทันที เมื่อครูแจ้งว่าเช็กชื่อไม่ได้ ให้ดูกล่องนี้ก่อน

เวลาและวัน

  • เปิด / ปิด: ค่าเริ่มต้น 07:30 / 08:30 (นับถึง 08:30:59)
  • วันเข้าแถวปกติ: ค่าเริ่มต้น จ–ศ วันอื่นให้ใช้ปฏิทิน

พื้นที่เข้าแถว (Geofence)

  1. พิมพ์ค้นหา เช่น "วิทยาลัยเทคนิคชัยภูมิ" หรือแตะ ◎ ตำแหน่งฉัน ขณะยืนที่ลาน
  2. เลื่อนแผนที่ให้หมุด 📍 กลางจอชี้กลางลาน (ปุ่ม 🛰 ดาวเทียมช่วยดูหลังคา)
  3. ตั้ง รัศมี (เริ่ม 150 ม.) และ ความคลาดเคลื่อน GPS สูงสุด (เริ่ม 100 ม.)

ควรทดสอบเดินเช็กชื่อ 4 จุด (กลางลาน ขอบลาน นอกพื้นที่ จุดอับสัญญาณ) ด้วยมือถือหลายรุ่น รัศมีกว้างเกินไปจะทำให้เช็กจากห้องพักครูได้

นำเข้า/ส่งออกผู้ใช้ด้วย Excel

เพิ่มหรือแก้ไขผู้ใช้หลายคนพร้อมกันได้จากไฟล์ Excel เปิดที่ เพิ่มเติม → นำเข้า/ส่งออกผู้ใช้ และ API (แท็บ Excel) หรือปุ่ม 📤 นำเข้า/ส่งออก ที่หน้าผู้ใช้และสิทธิ์ เหมาะกับงานต้นภาคเรียนหรือเมื่อมีบุคลากรย้ายเข้า-ออกหลายคน

  1. กด ⬇ แม่แบบ .xlsx ได้ไฟล์ที่มีหัวคอลัมน์ รายการให้เลือก (บทบาท แผนก) ชีต "วิธีกรอก" และชีต "แผนกที่มีในระบบ"
  2. กรอกหนึ่งแถวต่อหนึ่งคน ลบแถวตัวอย่างหรือพิมพ์ทับได้ จะใช้ไฟล์จากระบบสารบรรณฯ หรือไฟล์ที่ส่งออกจากหน้านี้แทนก็ได้
  3. แตะกรอบ เลือกไฟล์ .xlsx ระบบตรวจทั้งไฟล์ทันทีแต่ยังไม่บันทึก
  4. ตรวจตัวเลขสรุป แตะแต่ละกล่องเพื่อกรองดูเฉพาะแถวนั้น: สร้างใหม่ · แก้ไข (บอกค่าเก่า → ใหม่) · ไม่เปลี่ยน · ผิดพลาด (ข้าม) พร้อมเหตุผล
  5. กด บันทึก … รายการ แล้วยืนยันด้วยรหัสผ่าน แถวที่ผิดจะถูกข้าม แถวอื่นบันทึกตามปกติ

API เชื่อมต่อระบบภายนอก

ใช้เมื่อระบบอื่นของวิทยาลัย (เช่น ระบบบุคลากร ระบบสารบรรณ) ต้องการส่งรายชื่อเข้ามาอัตโนมัติ หรือดึงผลเข้าแถวไปใช้ กติกาเพิ่ม/แก้ไขผู้ใช้เหมือนนำเข้า Excel ทุกข้อ จัดการที่ เพิ่มเติม → นำเข้า/ส่งออกผู้ใช้ และ API แท็บ API เชื่อมต่อระบบภายนอก

  1. ตั้งชื่อกุญแจตามระบบที่จะเชื่อม เลือกสิทธิ์เท่าที่จำเป็น (ตารางด้านล่าง)
  2. ถ้าระบบปลายทางมี IP คงที่ ใส่ในช่อง อนุญาตเฉพาะ IP และเลือกอายุกุญแจได้ (30 วัน / 6 เดือน / 1 ปี / ไม่หมดอายุ)
  3. กด 🔑 สร้างกุญแจ แล้วยืนยันรหัสผ่าน
  4. กด คัดลอก ทันที กุญแจแสดงครั้งเดียว ปิดกล่องแล้วดูอีกไม่ได้ ถ้าหายต้องสร้างใหม่
  5. ส่งกุญแจกับไฟล์ API.md ให้ผู้ดูแลระบบปลายทางทางช่องทางที่ปลอดภัย ไม่ส่งทางแชตกลุ่ม

ระบบประเมินหรือรายงานต้องใช้ผลเข้าแถว

  • หนึ่งกุญแจต่อหนึ่งระบบ รายการ กุญแจทั้งหมด บอกเวลาที่ใช้ล่าสุดและจำนวนครั้ง กุญแจที่ไม่ได้ใช้แล้วควรยกเลิก
  • สงสัยว่ากุญแจรั่ว กด ยกเลิก ทันที มีผลทันที แล้วสร้างกุญแจใหม่ให้ระบบปลายทาง
  • การเพิ่ม/แก้ไขผู้ใช้ผ่าน API บันทึกลงประวัติผู้ดูแล ในชื่อผู้สร้างกุญแจพร้อมชื่อกุญแจ
  • ระบบปลายทางเรียกได้ไม่เกิน 120 ครั้งต่อนาทีต่อกุญแจ เอกสารสำหรับนักพัฒนาอยู่ในไฟล์ API.md

4. แบบรายงาน ผู้ลงนาม และอีเมล (☰ → 🖋)

  • ผู้ลงนาม 3 ลำดับ: แต่ละลำดับตั้งตำแหน่ง (แสดงใต้ลายเซ็น) ผู้ลงนาม และคำท้าย ค่าปัจจุบันตามแบบสรุปการปฏิบัติงานประจำวัน: หัวหน้างานบริหารและพัฒนาทรัพยากรบุคคล (ผู้รายงาน) → รองผู้อำนวยการฝ่ายบริหารทรัพยากร (ผู้ตรวจสอบ) → ผู้อำนวยการ (เลือก ทราบ/มอบ ตอนลงนาม)
  • เมื่อบันทึกผู้ลงนาม: ระบบใส่ตำแหน่งในโปรไฟล์ให้ (ถ้ายังว่าง) และให้ลำดับ 2–3 มีบทบาทผู้บริหารอัตโนมัติ
  • เอกสารที่สร้างแล้วไม่เปลี่ยนตาม: เปลี่ยนผู้ลงนามมีผลกับเอกสารที่สร้างหลังจากนั้น
  • หน่วยงานในแบบรายงาน: รวมแผนก/งานเป็น 16 หน่วยงานตามแบบฟอร์มกระดาษเดิม (ใช้ในรายงานผู้บริหาร) แก้ชื่อและลำดับได้ ควรตรวจจำนวนคนให้ตรงแบบฟอร์มเดิม
  • อีเมล: ดูสถานะและส่งอีเมลทดสอบ การตั้งค่า SMTP ทำที่เซิร์ฟเวอร์ (คู่มือนักพัฒนา)
  • รูปแบบเอกสาร: หนังสือราชการ ไม่มีกรอบ TH Sarabun 16 พอยต์ ระยะขอบ A4 บน 2.5 ซ้าย 3 ขวา 2 ล่าง 2 ซม.
  • แก้ไข / ลบเอกสาร: เจ้าหน้าที่บุคลากรทุกคนและผู้ดูแลระบบ แก้ได้เมื่อยังไม่มีผู้ลงนามหรือถูกส่งกลับ (แก้ข้อมูล วันที่ ชื่อ แล้วส่งฉบับเดิมลงนามใหม่) ลบได้ก่อนอนุมัติ เอกสารที่อนุมัติแล้วลบได้เฉพาะผู้ดูแลระบบ (ยืนยันรหัสผ่าน) รายละเอียดในคู่มือเจ้าหน้าที่บุคลากร หัวข้อ 6

หลังตั้งผู้ลงนามแล้ว ให้แจ้งทุกท่านเข้าระบบครั้งแรกและบันทึกลายเซ็น หน้าเอกสารจะแสดง "⚠ ยังไม่เคยเข้าสู่ระบบ" ใต้ชื่อผู้ที่ยังไม่พร้อม

สร้างข้อมูลย้อนหลัง 1–18 สัปดาห์ให้ทุกคน ไม่ทับข้อมูลจริง รายงานขึ้นป้าย "มีข้อมูลจำลอง" ใช้อบรมผู้ใช้ รวมงานบุคลากร: ลาป่วย/ลากิจ/ลาอื่น ๆ ไปราชการ งานนโยบาย พร้อมรายละเอียด ผู้มาสาย/ไม่ลงเวลากลับ และ (เลือกได้) ประเภทบุคลากรตัวอย่างให้คนที่ยังไม่กำหนด — เจ้าหน้าที่บุคลากรฝึกสร้างรายงานสรุปประจำวันได้ทันที

🧹 ลบข้อมูลจำลอง

ลบเฉพาะข้อมูลจำลอง รวมประเภทบุคลากรตัวอย่าง (ประเภทที่กำหนดเองไม่ถูกแตะ) จำลองใหม่ได้ทุกเมื่อ

⚠ ล้างข้อมูลทั้งหมด

ลบการเข้าแถว รูป และเอกสารรายงานทั้งหมด (บัญชีผู้ใช้ยังอยู่) ต้องพิมพ์ "ล้างข้อมูลทั้งหมด" ควรสำรองก่อน

ก่อนเริ่มใช้จริง: สำรองข้อมูล → ล้างข้อมูลทั้งหมด (ลบทั้งข้อมูลจำลองและข้อมูลทดสอบ) → ตั้งเวลาและวิธีเช็กชื่อให้ถูกต้อง

ไฟล์กู้คืนทั้งระบบ lineup-full-….tar (ฐานข้อมูล + รูปหลักฐาน + ลายเซ็น)

กู้คืนเมื่อข้อมูลเสียหายหรือย้ายเซิร์ฟเวอร์

1) สำรองข้อมูล

  • อัตโนมัติ: เที่ยงคืนหลังวันทำการ (อ.–ส. 00:00 น.) เก็บ 60 วัน ทั้งฐานข้อมูลและรูปหลักฐาน
  • 💾 สำรองตอนนี้: ไฟล์ขึ้นภายในประมาณ 1 นาที ใช้ก่อนล้างข้อมูลหรืออัปเดตระบบ
  • ไฟล์สำรองทั้งระบบ: แต่ละรอบมีปุ่ม ⬇ ไฟล์กู้คืนทั้งระบบ (.tar) ส่วนปุ่ม อื่น ๆ มีไฟล์ฐานข้อมูล .sql (เปิดด้วย phpMyAdmin / MySQL Workbench / HeidiSQL) .sql.gz และรูป/ลายเซ็น .tar.gz แยกกัน
  • ควรดาวน์โหลดไฟล์กู้คืนทั้งระบบเก็บไว้นอกเซิร์ฟเวอร์อย่างน้อยสัปดาห์ละครั้ง (เช่น ไดรฟ์ของวิทยาลัย) เพราะไฟล์สำรองอัตโนมัติอยู่บนเครื่องเดียวกับระบบ

2) กู้คืนระบบ

ใช้เมื่อข้อมูลเสียหาย ถูกลบผิด หรือย้ายไปเซิร์ฟเวอร์ใหม่ ข้อมูลปัจจุบันทั้งหมดจะถูกแทนที่ด้วยไฟล์สำรอง

  1. หัวข้อ 3 กู้คืนระบบ เลือกแหล่ง: จากไฟล์สำรองบนเซิร์ฟเวอร์ (เลือกรอบ) หรือ อัปโหลดไฟล์จากเครื่อง (lineup-full-….tar หรือ db-….sql.gz ไม่เกิน 1 GB)
  2. ไฟล์ที่อัปโหลดถูกตรวจก่อน ถ้าไม่ใช่ไฟล์สำรองของระบบนี้จะถูกปฏิเสธ
  3. ติ๊ก คืนรูปหลักฐานและลายเซ็นด้วย (แนะนำ)
  4. พิมพ์คำว่า กู้คืนระบบ แล้วกด ⚠ กู้คืนระบบ → ยืนยันรหัสผ่าน
  5. รอ 1–3 นาที หน้าเดิมแสดงผล “✓ กู้คืนระบบสำเร็จ” แล้วกด เข้าสู่ระบบใหม่
  • สำรองก่อนกู้อัตโนมัติ: ระบบสำรองข้อมูลปัจจุบันก่อนทุกครั้ง (เหตุผล “ก่อนกู้คืนระบบ”) ถ้ากู้ผิดรอบ กู้คืนจากรอบนั้นกลับมาได้
  • ไฟล์รุ่นเก่าใช้ได้: ระบบปรับโครงสร้างตารางให้เป็นรุ่นปัจจุบันหลังกู้คืน
  • ระหว่างกู้คืน: ผู้ใช้อาจใช้งานไม่ได้ชั่วคราว ควรทำนอกเวลาเช็กชื่อ หลังกู้คืนทุกคนอาจต้องเข้าสู่ระบบใหม่ รหัสผ่านตามข้อมูลในไฟล์สำรอง
  • เซิร์ฟเวอร์เสียทั้งเครื่อง: ให้นักพัฒนาติดตั้งเครื่องใหม่ตาม INSTALL.md → เข้าด้วย admin ของเครื่องใหม่ → อัปโหลดไฟล์ lineup-full-….tar ล่าสุดแล้วกู้คืน
  • หน้าเว็บเปิดไม่ได้: นักพัฒนากู้คืนด้วยคำสั่งบนเซิร์ฟเวอร์ (INSTALL.md หัวข้อ สำรองและกู้คืนระบบ)

3) ส่งออก Excel เพื่อทำรายงานต่อ

เลือกช่วงวันที่ ได้ 8 แผ่นงาน: ภาพรวม · รายบุคคล · รายแผนก · รายหน่วยงาน · รายวัน (ทุกแผ่นมีร้อยละ) · บันทึกการเข้าแถวทุกรายการ · บุคลากร · ปฏิทิน

ทุกปุ่มในหน้านี้ต้องยืนยันรหัสผ่านและบันทึกในประวัติผู้ดูแล ไฟล์มีข้อมูลส่วนบุคคลของบุคลากรทั้งหมด เก็บในที่ปลอดภัยและอย่าส่งต่อในกลุ่มแชท

7. เปิดการเข้าสู่ระบบด้วย LINE

ปุ่ม "เข้าสู่ระบบด้วย LINE" จะซ่อนอยู่จนกว่าจะตั้งค่า LINE Login channel (ฟรี)

  1. เข้า developers.line.biz → Create a new provider (เช่น "วิทยาลัยเทคนิคชัยภูมิ")
  2. Create a LINE Login channel → App types: Web app
  3. แท็บ LINE Login → Callback URL: https://lineup.ccollege.ac.th/api/auth/line/callback
  4. เปลี่ยนสถานะ channel เป็น Published
  5. คัดลอก Channel ID และ Channel secret ให้นักพัฒนาใส่ในเซิร์ฟเวอร์ (Channel secret เป็นรหัสลับ)

หลังเปิดใช้: ครูเข้าด้วยรหัสผ่านครั้งแรก → โปรไฟล์ → เชื่อมบัญชี LINE ครั้งต่อไปกดเข้าด้วย LINE ได้เลย ระบบไม่สร้างบัญชีใหม่จาก LINE และ 1 บัญชี LINE เชื่อมได้กับครู 1 คนเท่านั้น

9. เปิดรีเซ็ตรหัสผ่านทางอีเมล (SMTP)

ลิงก์ ลืมรหัสผ่าน? ทำงานเมื่อเซิร์ฟเวอร์มีบัญชีส่งอีเมล รหัสอีเมลเป็นความลับ ให้ผู้ดูแลเซิร์ฟเวอร์ตั้งเอง ไม่ส่งทางแชต

  1. ใช้ Gmail ของวิทยาลัย 1 บัญชี เปิด การยืนยัน 2 ขั้นตอน ที่ myaccount.google.com → ความปลอดภัย
  2. สร้าง รหัสผ่านสำหรับแอป (App passwords) ชื่อ “lineup” ได้รหัส 16 ตัวอักษร
  3. แก้ไฟล์ /opt/lineup/deploy/.env บนเซิร์ฟเวอร์ เพิ่ม SMTP_HOST=smtp.gmail.com SMTP_PORT=587 SMTP_USER=<บัญชี> SMTP_PASS=<รหัส 16 ตัว> SMTP_FROM=ระบบเช็กชื่อเข้าแถว <บัญชี>
  4. สั่ง cd /opt/lineup/deploy && sudo docker compose up -d app
  5. ทดสอบ: หน้าตั้งค่า → อีเมล → ส่งอีเมลทดสอบ แล้วลอง “ลืมรหัสผ่าน?” ด้วยบัญชีทดสอบ (ลิงก์ใช้ได้ครั้งเดียว)

อีเมลส่งถึงเฉพาะคนที่มีอีเมลในระบบ เติมทีละคนที่หน้าผู้ใช้ หรือทั้งหมดด้วย Excel (คอลัมน์อีเมล) คนที่ไม่มีอีเมล ผู้ดูแลระบบยังรีเซ็ตรหัสให้ที่หน้าผู้ใช้ได้ตามเดิม
